# build: qualify container through isolated Bazel layers

## Motivation and Context

The family-wide workflow repeatedly rebuilt unrelated repositories and made failures difficult to locate. Preserve the baseline and limit the active graph to container, its 39 required Swift dependencies, and its same-repository Go helper. See [ISSUE-289.md](ISSUE-289.md).

## Implementation

Expose native Bazel build and test targets by dependency layer, with immutable package pins, declared fixtures and persistent SSD caches. Host permissions, Linux, VM and CLI integration remain explicit layers. Guest, builder and service artifacts use separate caches and verified source/toolchain receipts.

The unattended command runs the original maintenance, protocol generation, documentation, service, VM and CLI checks with bounded execution and owned-resource cleanup. Build tests remove their shared private builder before System tests assert an empty image store. Unit, integration and combined line coverage retain source-bound LCOV, XML, JSON summaries and HTML. Integration profiles the actual CLI and services, restores the original binaries even after export failure, and rejects setup-only counters or incomplete combined evidence. Sonar retains unit-only coverage, the exact commit as project version, Previous version policy, and the original zero-issue/hotspot checks. CodeQL uses a pinned traced compiler build and retains SARIF.

Packaging uses the original signed archive and debug-symbol recipes, persists notarization results, and tests installation in a private location before restoring its predecessor. Component and optimized Apple/fork/Docker benchmarks retain raw durations, output checks and exact artifact identities. Manual GitHub execution checks out the dispatch SHA on a named branch and invokes the same command; it requires a designated self-hosted Mac runner.

Live integration also fixes regular-file stdin EOF handling, which otherwise left kubectl waiting after receiving input. Empty and multi-chunk inputs have a failing-before/passing-after regression. The containerization pin includes the VSOCK descriptor-transfer correction verified by the native VM suite. Socket fixtures use a pinned Python image, and the overlapping TCP stress cases run serially in both benchmark lanes while preserving their internal concurrency and assertions.

## Compatibility and Remaining Risks

Existing SwiftPM and upstream workflows remain available. Four upstream NIO host checks remain known macOS failures with unchanged assertions. The fork's longer container-name limit and different rejected-certificate TLS alerts remain failed upstream compatibility assertions without speed ratios; any extra failure, timeout or tenfold slowdown fails qualification. Unit coverage (63.38%) and builder coverage (49.2%) remain below the 90% aim, with the gaps visible rather than hidden by low-value tests.

Final complete integration/combined coverage, updated source qualification, runtime benchmarks and package/install proof remain pending. Apple accepted the earlier pilot notarization `aa97fc82-3cd8-45f8-b9d2-48157926eb4b`; it is not the final package. The archive distribution is signed/notarized; the native PKG is explicitly unsigned because no Installer certificate is configured. Local qualification imports exact guest/builder archives and does not claim unpublished default registry references are available. This command creates release candidates without publishing them or replacing the user's installed runtime. Compose/devcontainer and unrelated family repositories stay outside scope.
