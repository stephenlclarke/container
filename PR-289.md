# build: qualify container through isolated Bazel layers

## Motivation and Context

The family-wide workflow repeatedly rebuilt unrelated repositories and made failures difficult to locate. Preserve the baseline and limit the active graph to container, its 39 required Swift dependencies, and its same-repository Go helper. See [ISSUE-289.md](ISSUE-289.md).

## Implementation

Expose native Bazel build and test targets by dependency layer, with immutable package pins, declared fixtures and persistent SSD caches. Host permissions, Linux, VM and CLI integration remain explicit layers. Guest, builder and service artifacts use separate caches and verified source/toolchain receipts.

The unattended laptop command runs the original maintenance, protocol generation, documentation, service, VM and CLI checks with bounded execution and owned-resource cleanup. Build tests remove their shared private builder before System disk accounting. Local unit, integration and combined line coverage retain source-bound LCOV, XML, JSON and HTML; runtime profiling restores original binaries even after export failure. GitHub runs `sonar.yml`: parallel same-revision jobs perform native unit coverage/SonarCloud and a fresh arm64 CodeQL build of all default production products, then enforce the original strict SonarCloud and zero-finding SARIF gates. Local admission requires both jobs from the same newest attempt. Exact commit versions, Previous version policy, unchanged thresholds, zero issues/hotspots and zero CodeQL findings remain required. Local scanners are removed from standard qualification and preflight.

VM qualification opts into the dependency's existing runc tests using a separate guest variant with its source-pinned runtime checksum. It reuses compiled guest binaries, retains the base guest for runtime benchmarks/release, and rejects every skip except the two named unsupported-graphics cases. Prior 191-pass/22-skip runs omitted 20 runc tests and had two graphics-capability skips; they are not complete VM qualification. The corrected live suite at `6b94960b` passed 211 tests with only those two graphics skips, verified VM cleanup and restored the original services.

Packaging uses the original signed archive and debug-symbol recipes, persists notarization results and tests installation privately before restoring its predecessor. Component and optimized Apple/fork/Docker benchmarks retain raw durations, output checks and exact artifact identities. The wrapper holds the common host runtime lock, quiesces only authorized idle workers and restores them after verified cleanup. Before packaging, it requires the newest hosted run and its successful `Analyze Swift` job for the same commit and PR/base context; local main must match current pushed main. Skipped jobs and pending/failed newer attempts cannot qualify release. GitHub no longer dispatches heavy self-hosted qualification or automatic Stephen package publication; duplicate native PR/main builds are suppressed. Upstream Apple paths, commit-signature and lightweight formula checks remain. Release preflight checks native DNS against the unchanged proxy deadline; original guest lookup remains required without retries or overrides.

Benchmark qualification now admits the exact published Q153 historical asset before runtime work. Candidate-only preparation avoids stock builds and measurements; the final runtime comparison imports all 56 original Apple samples unchanged. Component and Docker reuse retain source/workload/environment checks and explicit historical provenance. Current functional tests and output validation remain required, and reused rows are not evidence of fresh execution. A changed reference contract fails closed. Focused offline tests cover reference tampering, admission drift and refusal to execute stock commands; new live qualification is still pending.

Live integration also fixes regular-file stdin EOF handling, which otherwise left kubectl waiting after receiving input. Empty and multi-chunk inputs have a failing-before/passing-after regression. The containerization pin includes the VSOCK descriptor-transfer correction verified by the native VM suite. Socket fixtures use a pinned Python image, and the overlapping TCP stress cases run serially in both benchmark lanes while preserving their internal concurrency and assertions.

The later foreground pipe case exposed a distinct EOF boundary: a finite script reached its last guest command, but primary stdin remained open and `sh` did not exit. The primary non-TTY interactive `run`/`start` bootstrap now requests EOF closure after buffered bytes drain; the request crosses the dedicated, prewarm and shared workload paths. TTY, detached and subsequent attach sessions retain their prior policy. A focused input-stream regression failed before the change and passed afterward. Seven targeted Bazel test suites passed across the main and one corrected test-fixture rerun, including runtime, API service, command and K8s suites. No new live CLI result is claimed by those unit tests.

Private archive installation persists original fingerprints and recovery authority before replacing files. Log-copy failure cannot skip restoration, surviving processes prevent replacement, and the outer wrapper verifies restoration before resuming workers. Missing or incomplete restoration evidence preserves the host recovery journal and leaves workers quiesced. Focused fault tests cover log-copy failure, cancellation, failed initial/restore moves, surviving processes, changed binaries and incomplete receipts.

Explicit `make bazel-recover` handles a wrapper killed before its final cleanup. It verifies the exact invocation and dead owner, holds the existing host/runtime locks and requires exclusive access to the command lease inherited by controllers and Colima commands. An idle Bazel daemon can retain that lease after its client exits: cleanup requests official nonblocking shutdown of the recorded workspace and then must reacquire exclusive ownership. A busy server or surviving controller still blocks restoration; caches are preserved. Recovery reconciles saved registrations even when cancellation interrupted receipt updates. Uncertain binary replacement keeps workers paused and never manufactures successful qualification. Scheduled launchd respawns remain ineligible for ordinary inactive-service admission.

The same recovery command now handles a recorded failed profiling-install swap after its owner has exited. It authenticates the clean recorded source, owned paths, both idle installations and their original/instrumented fingerprints before calling existing coverage cleanup with a failed test result. The first failed coverage record is preserved unchanged; subsequent failures may be appended and a verified retry remains possible. Redirected evidence, active owners/processes, conflicting locks or altered fingerprints prevent replacement. A missing journal still requires verified restoration, and an unrecorded post-replacement outcome remains a failure requiring reconciliation.

The maintained signed runner app and previous setup evidence are retained, but are not required for hosted quality or direct laptop qualification. Its stable Local Network grant does not certify the original HTTP integration test. Optional exact-identity local configuration permits a temporary operational stop of the diagnosed failed API only after other admission passes and clients are quiesced. It checks failure state, absent runtime processes and stopped saved records twice, journals restoration authority before stopping, then rechecks state. It neither repairs the original provider binding nor certifies live inventory.

Native SwiftPM commands and upstream Apple workflows remain available; Stephen's duplicate builds and automatic packaging paths are retired. Four upstream NIO host checks remain known macOS failures with unchanged assertions. Longer container names and rejected-certificate TLS alerts remain failed upstream compatibility assertions without speed ratios; any extra failure, timeout or tenfold slowdown fails qualification. Local unit coverage (63.38%) and builder coverage (49.2%) remain below the 90% aim. Hosted Sonar uses unit-only coverage, while full integration and combined coverage remain separate laptop gates; thresholds are not reduced to accommodate this split. Both hosted analysis and complete local qualification must still pass at the final revision.
