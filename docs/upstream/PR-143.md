# Pull request handoff: run container VM boots concurrently

## Summary

- Capture container state, lifecycle generation, path, and configuration under a short host-wide lock section.
- Perform logging preparation, network resolution, launchd registration, runtime-client creation, and VM bootstrap outside the host-wide lock.
- Reacquire the lock to generation-fence and atomically commit the runtime client and token.
- Preserve same-ID lifecycle serialization and failure cleanup.
- Record one debug timing summary containing monotonic per-phase durations.

## Code map

- `Sources/Services/ContainerAPIService/Server/Containers/ContainersService.swift` adds container-instance generations, the two-phase bootstrap plan and commit, token-matched failure cleanup, and phase timing metadata.
- `Tests/ContainerAPIServiceTests/ContainerBootstrapConcurrencyTests.swift` proves copied state retains identity while a replacement receives a new generation, and proves stale container or lifecycle generations cannot pass the commit fence.
- `docs/upstream/ISSUE-124.md` records the problem, required behavior, evidence, and remaining parent-contract limit.

## Release benchmark

The seven-repetition, warm-image, counterbalanced comparison froze the Compose binary, Containerization plugins, OCI image, Docker oracle, fixtures, host, and schedule. The benchmark changed the version-bearing Container CLI and API server to commit `01ccfb6b7008b6a23d9198d4fc3bc90170e621bb`.

Ten-service median startup improved from 5.244s to 1.611s, a 69.3% reduction. Fifty-service median startup improved from 25.742s to 16.411s, a 36.2% reduction. Functional Docker parity passed for every measured startup and teardown fixture.

The project-wide performance guard remains open. Fifty-service startup P95 is 22.674s, or 11.77x Docker, and one-service startup median moved from 0.908s to 1.031s in this run. This pull request is one bounded improvement rather than a claim that issue 124 or the Compose parent contract is complete.
