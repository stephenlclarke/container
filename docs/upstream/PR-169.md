## Review corrections

The review-to-clean loop found and fixed real integration and documentation
defects:

- Apple's new tmpfs tests needed exhaustive handling for this fork's image
  mount result.
- The dependency graph still selected a pre-refresh SwiftNIO SSL revision.
- The imported skill omitted shipped attach, top, pause, unpause, events,
  resize, adaptive memory, shared-VM, DNS, Compose, and fork-install behavior.
- Machine examples used images without a compatible init, conflated the Linux
  home with the separately mounted macOS home, and omitted host working-directory
  inheritance.
- Network and volume compatibility claims were broader than the implemented
  subcommands.
- The networking guidance promised a distinct per-container IP for `none` and
  shared-VM host networking, where that promise does not hold.
- The machine guide presented the nested `m` subcommand alias as a standalone
  executable.
- The migration guide said the shipped restart policy was unavailable and
  overgeneralized distinct-IP guidance beyond default and custom networks.
- The nested-virtualization sequence reset its kernel instead of showing the
  required reboot.
- Docker's memory-only update path was not mapped to the supported live resize
  command and its dedicated-VM bounds.
- The exact full gate exposed a race in the GELF EOF-reconnect regression: a
  valid probe frame could satisfy the capture promise before the golden frame.
  The test capture now skips complete non-matching frames and retains its
  bounded wait for the exact production frame.

Each inline finding has an explicit response and is resolved only after its fix
is present on the pull-request branch.
