# Pull request handoff: explicit shared-VM container lifecycle

## Summary

- Add explicit `dedicated-vm` and experimental `shared-vm` isolation choices while retaining dedicated VM isolation when the option is omitted.
- Persist requested/effective isolation and the immutable shared sandbox identity.
- Route the initial ordinary shared workload lifecycle through the existing durable Engine Linux sandbox authority without a per-container launchd helper.
- Generation-fence state, wait, signal, resize, statistics, process listing, service dial, pause, resume, stop, natural exit, and API-server boot reclamation.
- Reject unsupported or unsafe shared configurations without silently falling back to dedicated isolation.

## Code map

- `Sources/ContainerResource/Container/ContainerIsolationMode.swift` and `ContainerConfiguration.swift` define and persist the public isolation contract.
- `Sources/Services/ContainerAPIService/Client` parses the CLI option and rejects configurations outside the first safe shared boundary.
- `Sources/Services/ContainerAPIService/Server/Containers/ManagedRuntimeClient.swift` preserves the existing dedicated client and adapts ordinary containers to the shared authority.
- `Sources/Services/ContainerAPIService/Server/Containers/EngineLinuxSandboxAuthority.swift` owns durable, effectless workload control and API-server boot reclamation.
- `Sources/Services/RuntimeLinux/Server/EngineLinuxSandboxRuntimeService.swift` applies exact-generation workload control inside the shared Linux sandbox.
- `docs/command-reference.md` describes the security boundary, supported lifecycle, and explicit follow-ons.

## Security and scope

`shared-vm` is an explicit experimental trade-off: workloads share one VM kernel/security boundary. `dedicated-vm` remains the default and stronger boundary.

The first vertical admits native Linux workloads using exactly `--network none` or `--network host`. Initial attached run/start streams work. Attach after start, exec, copy, runtime log following, health checks, published TCP/UDP ports, bridge/custom networking, custom VM assets, Rosetta, devices, GPUs, nested virtualization, privileged workloads, host namespace escapes, and live snapshots remain follow-ons.

This pull request is a partial slice and does not close the parent sandbox-authority parity issue.
