# Pull request handoff: pin the published VM-init authority

## Summary

- Pin the Containerization dependency to the exact merged revision published
  by the fork's trusted main workflow.
- Keep `Package.swift` and `Package.resolved` on the same immutable revision.
- Record anonymous registry resolution and clean-runtime evidence.

## Type of Change

- [x] Bug fix
- [ ] New feature
- [ ] Breaking change
- [x] Documentation update

## Motivation and Context

The enhanced runtime compiles its default VM-init image reference from the
Containerization dependency revision. The previous fork revision was not
published under `ghcr.io/stephenlclarke/containerization/vminit`, so a clean
installation could not boot without a cached archive or personal override.

Fixes <https://github.com/stephenlclarke/container/issues/265>.

## Design choices

The pin advances only after source revision
`aa6b0bdeef888b52afaf290cc7ac1909c3ac6fe5` is published by the
trusted Containerization main workflow and is anonymously resolvable. This
keeps source, image, runtime, and downstream release identities mechanically
coupled without adding Docker or a mutable fallback tag.

## Compatibility

The change retains the stock Apple runtime interface and only repairs the
enhanced fork's immutable default asset. Existing explicit image overrides
remain supported.

## Remaining risks

The downstream Compose pin and Homebrew release must be updated atomically
after this merge. Until then, the already published stable release still
references the prior missing image.
