# fix(commit): preserve the effective image command split

## Motivation

Committing a container must preserve whether its command is replaceable. Flattening the initial process into `Entrypoint: [executable]` and `Cmd: arguments` changes subsequent command overrides and loses multi-element entrypoints. Addresses [apple/container #2350](https://github.com/apple/container/issues/2350).

## Implementation

`ProcessConfiguration` gains optional, Codable `ImageCommand` metadata containing the effective entrypoint and command. The client parser computes that split before flattening the runtime argv, preserving omitted and explicit empty arrays. Image creation uses the persisted split when it agrees with the runtime argv; stale metadata from a caller that changed the process is ignored.

Legacy records and API callers without metadata remain readable. Image creation preserves the source entrypoint when it matches the process prefix; images without an entrypoint retain the full process as their command. A historical explicit override cannot always be recovered from argv alone, so a mismatching legacy source entrypoint retains the prior executable/arguments fallback. New parser-created records avoid that ambiguity.

## Validation

The regression creates and extracts real OCI archives after encoding and decoding the process configuration. Eight cases cover inherited commands, positional overrides, multi-element entrypoints, clearing, empty overrides, explicit replacements, and identical argv with different requested splits. Persistence tests cover old records and nil versus empty arrays. The original implementation failed the archive regressions with 14 assertion issues; raw results are retained outside the source checkout.

Focused parser, persistence and archive tests pass with warnings treated as errors against the selected SDK revision. Formatting/license checks and Markdown lint pass. The source candidate also consumes Containerization `fbe69a32f672f05f171961d26862baaf53734f41`, whose sparse-file read/export correction for [apple/containerization #958](https://github.com/apple/containerization/issues/958) passes all 102 EXT4 tests, including malformed geometry and offset overflow. This prevents file-content corruption in the same commit/export path. The existing running/stopped commit integration fixture now checks the corrected image metadata and executes a replacement command. Full VM, Docker oracle, release and performance qualification remain pending against the coherent candidate checkpoint; unit results do not establish those gates.

## Compatibility and remaining risks

The process launched by existing parser paths is unchanged. The new optional JSON field is additive and old records decode without it. Legacy explicit entrypoint intent remains unrecoverable where runtime argv is ambiguous. No published baseline binary, measurement or provenance is modified.
