# Materialize and verify missing debug symbol bundles

## Change

Resolve [#283](https://github.com/stephenlclarke/container/issues/283) by
replacing unconditional `.dSYM` copies with a verified packaging tool. The
tool reuses a SwiftPM sidecar when available and otherwise invokes the active
Xcode `dsymutil` against the built executable.

The package now includes all eight Swift executables shipped by Container.
Every bundle must report exactly the same UUID and architecture set as its
source executable before the directory and zip archive are published. The
two artifacts are staged together, and prior artifacts are restored if
publication fails.

## Validation

- Eleven focused unit tests pass with 98% line coverage.
- Tests exercise existing and missing bundles, malformed output, UUID
  mismatch, missing products, unsafe and duplicate product names, atomic
  replacement, rollback, Xcode tool lookup, and CLI dispatch.
- Repository formatting and licence checks pass with pinned Hawkeye 6.5.1.
- `make dsym` passes against the exact retained Xcode 27 / Swift 6.4 build
  that blocked the Compose stable-release transaction.
- The recovered archive contains eight bundles, passes zip integrity, and
  reports matching arm64 UUIDs for every executable.

## Compatibility

The change is confined to release artifact generation. Runtime APIs and
behaviour are unchanged, and the implementation works with both the stock
Apple Container source layout and the enhanced fork. Compose does not need a
runtime workaround for this failure.
